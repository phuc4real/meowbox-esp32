# MeowBox REST API (v1)

Contract between the web UI (`web/src/`) and the firmware (`components/net/`).
The mock in `web/mock_server.py` implements exactly this document.

## General rules

- Transport: plain HTTP on port 80 (`http://meowbox-xxxx.local` or the device IP). JSON bodies are UTF-8,
  `Content-Type: application/json`. Request bodies are at most **8 KB**, except `/api/ota` and
  `/api/notify/audio`. A body must arrive within 5 s plus 1 s per 16 KB, else `408 {"err":"timeout"}` (or the
  connection is closed).
- Shapes are kept flat and short so the firmware can parse them with cJSON. Booleans are JSON `true`/`false`.
  Unknown fields are ignored, and a missing field in a `PUT` keeps its current value.
- Success: HTTP 200 with a JSON object (`{"ok":true}` when there is nothing else to return).
- Error: HTTP 4xx/5xx with `{"err":"<code>"}`. Codes: `auth` (401), `forbidden` (403), `bad_json` (400),
  `bad_value` (400), `not_found` (404), `too_large` (413), `too_many` (429), `busy` (503), `bad_image` (400),
  `bad_old` (403), `queue_full` (429), `timeout` (408), `def_pw` (403).
- `/api/*` answers only requests addressed to the speaker: a `Host` header (if sent) must be the speaker's IP,
  `192.168.4.1`, `meowbox-xxxx` or `meowbox`, optionally with `.local`, `.lan`, `.home`, `.home.arpa`,
  `.localdomain` or `.internal` and a port; an `Origin` header (if sent) must be `http://` + one of those.
  Anything else → `403 forbidden`. The web page itself is sent with `X-Frame-Options: DENY`.
- Times are Unix seconds (UTC). The device always uses the `ICT-7` time zone; the UI shows local times in ICT.

### Static files

| Path | File in LittleFS | Headers |
|---|---|---|
| `/`, `/index.html` | `/web/index.html.gz` | `Content-Type: text/html; charset=utf-8`, `Content-Encoding: gzip` |
| `/app.css` | `/web/app.css.gz` | `text/css`, gzip |
| `/themes.css` | `/web/themes.css.gz` | `text/css`, gzip (generated by `tools/gen_themes.py`) |
| `/app.js` | `/web/app.js.gz` | `application/javascript`, gzip |
| `/fonts/<file>` | `/web/fonts/<file>` (not gzipped) | `.woff2` → `font/woff2`, `fonts.json` → `application/json`. `Cache-Control: max-age=86400` is fine |
| `/themes/<id>.png` | `/web/themes/<id>.png` | `image/png`. Missing → `404`; the UI then draws a placeholder in that theme's colours |

`/fonts/fonts.json` maps each font file to its `@font-face` data:
`{"archivo-vi.woff2":{"family":"Archivo","weight":"400 800","style":"normal","stretch":"62% 100%"}, ...}`.
The UI loads only the files listed in the active theme's `fonts` (a listed name such as `chakra-petch-vi.woff2` that
is not in `fonts.json` also matches its variants `chakra-petch-400-vi.woff2`, ...). No `fonts.json` or files → the
system font stacks from `themes.css`. Nothing is ever loaded from a CDN (SoftAP mode has no internet).

Static files need no auth (the login screen is part of the app). They are embedded in the app image
(`components/webui/web.pack`, built by `web/build.py`), so the UI always matches the firmware. UI strings are static too:
`/lang/<code>.<hash>.json` (one JSON object per language, same keys); the page loads only the active one.
Caching: files whose name carries a content hash (`app.<hash>.js`, `lang/…`, `theme/…`, `themes.<hash>.css`) are sent
with `Cache-Control: public, max-age=31536000, immutable`; `fonts/*` and `themes/*.png` with `max-age=604800`;
`index.html` with `no-cache`. Every file has an `ETag`; a matching `If-None-Match` gets `304 Not Modified` with no body.
In SoftAP mode any unknown host redirects to `/` (captive portal).

### Authentication

| Path | Auth |
|---|---|
| `POST /api/login`, `GET /api/theme` | none |
| `/api/notify`, `/api/notify/audio`, `/api/notify/history` | **Bearer token** (`Authorization: Bearer <token>`), or `?token=<token>` on GET. The session cookie is also accepted so the web UI can use them. |
| every other `/api/*` | **session cookie** `sid` |
| `/ws/pc` | the notify token in the first message (`hello`), see below |

- Default credentials `meowbox` / `m3owb0x2026`. The password is stored as SHA-256(salt + password) in `/data/auth.json`.
  A device still on the pre-2026-11-23 default (`meowbox`) is moved to the new default on boot.
- Sessions: random 128-bit id, max 4 at a time (oldest dropped), expire after 24 h without use. Kept in RAM,
  so a reboot logs everyone out.
- Failed logins are counted per client address: after 5 in a row that address gets `429 too_many` for 30 s, and each
  further failure doubles the wait (up to 15 min). A correct login, or 15 min without a failure, resets it. Other
  devices are not affected. Passwords longer than 64 characters never match.
- Missing or invalid session → `401 {"err":"auth"}`; the UI then shows the login screen.
- While the default password is in use (`def_pw`), a session may only call `GET /api/session` and
  `POST /api/password` (and log out): everything else answers `403 {"err":"def_pw"}`, and the UI shows only the
  change-password form. Token routes still work with the token. A factory reset brings the default back.

## Session

### `POST /api/login`
```json
{"user":"meowbox","pass":"m3owb0x2026"}
```
→ `200`, `Set-Cookie: sid=9f2c...e1; Path=/; HttpOnly; SameSite=Strict`
```json
{"ok":true,"def_pw":true}
```
`def_pw` is true while the default password is still in use (the UI shows a banner). Wrong credentials → `401 {"err":"auth"}`.

### `POST /api/logout`
Body `{}`. Drops the session, clears the cookie. → `{"ok":true}`

### `GET /api/session`
→ `{"user":"meowbox","def_pw":true}` or `401`. Used by the UI at startup.

### `POST /api/password`
```json
{"old":"m3owb0x2026","new":"m30w-secret"}
```
`new` must be 6–32 characters. → `{"ok":true}`. Wrong `old` → `403 {"err":"bad_old"}`; bad length → `400 bad_value`.
All other sessions are invalidated.

## Status

### `GET /api/status`
```json
{
  "ver":"0.1.0","build":"2026-11-20 21:04","up":93784,
  "mode":"sta","ssid":"NhaMeo","ip":"192.168.1.50","rssi":-58,
  "bat":78,"chg":true,"usb":true,
  "heap":142336,"heap_min":98304,"psram":6815744,"psram_tot":8388608,
  "time":1763791200,"vol":40,"sleep":0,"pc":true,"def_pw":true,
  "play":{"st":"play","id":2,"name":"Lofi Girl","title":"Snowman - Kudasai"}
}
```
- `mode`: `sta` (connected), `ap` (SoftAP portal `MeowBox-XXXX`, WPA2), `conn` (connecting).
- `bat`: 0–100 or `-1` if unknown. `chg`: charging; `usb`: USB power present.
- `heap`/`heap_min`: free internal heap now/minimum since boot (bytes). `psram`/`psram_tot`: free/total PSRAM.
- `sleep`: seconds left on the sleep timer, 0 = off. `pc`: PC agent connected.
- `play.st`: `stop` | `buf` (connecting/buffering) | `play` | `err`. `id` is the station id, or 0 for an ad-hoc URL.
- `play.net` (only while a network stream is buffering, playing or failed; absent otherwise):
  `{"kbps":112,"br":128,"buf":9.3,"pre":6,"fill":100,"under":2,"reconn":0,"fmt":"mp3","err":""}`.
  `kbps` download rate (5 s average); `br` stream bitrate (`icy-br` header or decoder, 0 = unknown); `buf` seconds of
  audio buffered; `pre` seconds collected before playing (3/6/10: one step up after each underrun, down after 5 min
  without one, back to 3 when Wi-Fi reconnects); `fill` buffering progress in %; `under` underruns while playing;
  `reconn` reconnects; `fmt` `mp3`|`aac`|`ts`|`hls`; `err` last error `connect`|`http_<code>`|`read`|`stall` (under a quarter of the bitrate for 10 s while buffering: reconnected)|`decode`|`no_mem` or `""`.
  `title` is the ICY StreamTitle (may be empty).

## Wi-Fi

### `GET /api/config/wifi`
```json
{"cur":"NhaMeo","max":5,"nets":[{"ssid":"NhaMeo"},{"ssid":"VanPhong"}]}
```
Passwords are never returned. Order = connect priority.

### `PUT /api/config/wifi`
```json
{"nets":[{"ssid":"VanPhong"},{"ssid":"NhaMeo"},{"ssid":"Moi","pass":"12345678"}]}
```
Replaces the saved list (reorder/delete). An entry without `pass` keeps the stored password for that SSID;
a new SSID needs `pass` (empty string = open network). At most `max` entries. → same shape as GET.

### `GET /api/wifi/scan`
Blocking scan (~2–3 s). → sorted by RSSI, deduplicated by SSID:
```json
{"aps":[{"ssid":"NhaMeo","rssi":-52,"ch":6,"sec":true},{"ssid":"Cafe Free","rssi":-80,"ch":11,"sec":false}]}
```
`503 busy` if a scan is already running.

### `POST /api/wifi/connect`
```json
{"ssid":"NhaMeo","pass":"12345678"}
```
Saves the network at the top of the list and switches to it. → `{"ok":true}` is sent **before** switching;
the device may get a new IP (shown on its screen). Omit `pass` to reuse a saved password.

### `GET /api/wifi/portal` · `POST /api/wifi/portal`
State of the setup hotspot `MeowBox-XXXX` (WPA2; its password is made per speaker at first boot and after a
factory reset, and shown only on the speaker's screen and in its Wi-Fi QR code). **Token auth** (`Authorization:
Bearer <notify token>`), a web session also works, so the PC agent can reopen it.
```json
{"on":true}
```
→ `{"on":true,"ssid":"MeowBox-A1B2","off_in":587}`
- `off_in`: seconds until a hotspot opened while online closes by itself (10 min without clients),
  `"client"` while a device is connected (timer paused), `null` when off or while offline.
- With no saved network it opens by itself (first boot); with saved networks only after 5 min without Wi-Fi.
- The hotspot also closes 10 s after the speaker joins Wi-Fi. While offline it stays on: `{"on":false}`
  then returns `409 offline`. `on` must be a bool, otherwise `400 bad_value`.
- On the speaker: hold VOL+ and VOL− together for 3 s, or System tile → "Wi-Fi".

## Radio

### `GET /api/config/radio`
```json
{
  "vol":40,"last":2,"max":50,
  "st":[
    {"id":1,"name":"VOV3","url":"https://str.vov.gov.vn/vovlive/vov3.sdp_aac/playlist.m3u8","type":"hls"},
    {"id":2,"name":"Lofi Girl","url":"https://www.youtube.com/watch?v=jfKfPfyJRdk","type":"youtube"},
    {"id":3,"name":"Radio Paradise","url":"http://stream.radioparadise.com/mp3-128","type":"stream"}
  ]
}
```
- `type`: `stream` (MP3/AAC over HTTP/HTTPS, incl. `.pls`/`.m3u` already resolved), `hls` (`.m3u8`),
  `youtube` (`url` is the YouTube link; the firmware plays `http://<relay>/yt/stream?url=<urlencoded>` via the PC agent; `<relay>` comes from the agent's `hello` message on `/ws/pc` (`auto:true`) or from `host:port`).
- `id`: integer 1–65535, unique, stable (alarms reference it). New stations from the UI get `max(id)+1`.
- Array order = display order. `name` ≤ 48 bytes, `url` ≤ 256 bytes.

### `PUT /api/config/radio`
`{"st":[...]}` (full list, same item shape) and/or `{"vol":40}`. → same shape as GET.
Alarms that reference a deleted station fall back to `chime`. A station whose `url` does not start with `http://` or
`https://` → `400 bad_value` (nothing saved).

### `POST /api/radio/play`
One command per call:
```json
{"cmd":"play","id":3}
{"cmd":"play"}
{"cmd":"play","url":"http://ice.example/live.mp3","name":"Thử đài"}
{"cmd":"stop"}
{"cmd":"next"}
{"cmd":"prev"}
{"cmd":"vol","vol":55}
```
`{"cmd":"play"}` without `id`/`url` resumes the last station (`last`). `play` with `url` is a preview of a search result (not saved, `play.id` = 0). `vol` 0–100.
→ `{"ok":true,"vol":55,"play":{...same as status.play...}}`. Unknown id → `404 not_found`. A `url` that does not start
with `http://` or `https://` → `400 bad_value`.

### `GET /api/sleep`
→ `{"left":1200}` (seconds, 0 = off)

### `POST /api/sleep`
`{"min":30}` (one of 15/30/60/90 or any 1–240; `0` cancels). Stops the radio when it reaches 0. → `{"left":1800}`

## Alarms

### `GET /api/config/alarms`
```json
{"snooze":5,"max":5,"al":[
  {"on":true,"h":6,"m":30,"days":31,"snd":"chime","st":0},
  {"on":false,"h":8,"m":0,"days":96,"snd":"radio","st":3}
]}
```
- `days`: bitmask, bit0 = Monday … bit6 = Sunday (31 = Mon–Fri, 96 = Sat+Sun, 127 = every day, 0 = once).
- `snd`: `chime` | `radio`. With `radio`, `st` is the station id; if the stream fails, the chime plays.
- `snooze`: minutes (1–30). At most `max` alarms.

### `PUT /api/config/alarms`
Same shape (full `al` list). → same shape as GET.

## Weather

### `GET /api/config/weather`
```json
{"on":true,"name":"Hồ Chí Minh","lat":10.823,"lon":106.630,"unit":"c",
 "now":{"t":24.5,"code":3,"hi":28,"lo":20,"at":1763790000}}
```
`now` is read-only (last open-meteo result, `null` if none yet). `code` = WMO weather code. `unit`: `c` | `f`; the
device asks open-meteo for that unit, so `t`, `hi` and `lo` are in it, and the clock shows `°C` or `°F`.
The UI looks the city up itself at `https://geocoding-api.open-meteo.com/v1/search` and only sends the result.

### `PUT /api/config/weather`
`{"on":true,"name":"Đà Nẵng","lat":16.068,"lon":108.212,"unit":"c"}` → same shape as GET (the device refreshes now).

## Display

### `GET /api/config/display`
```json
{"bri":80,"idle_bri":20,"idle_s":60,"sleep_s":300,"h24":true,
 "night":true,"night_mode":"auto","n_from":22,"n_to":7,"n_bri":5,
 "lang":"vi","tz":"ICT-7","theme":"swiss","fx":"full"}
```
- `bri`, `idle_bri`, `n_bri`: 0–100. `idle_s`: dim after this many seconds without touch (0 = never).
- `sleep_s`: screen sleep after this many seconds without touch or a button (default 300, 0 = never). Backlight and
  panel off, drawing paused, mics off, amplifier off after 3 s of silence, CPU at 80 MHz unless audio plays. Wi-Fi,
  alarms, notifications and playback keep running; a card (alarm, notification) wakes the screen. The press or touch
  that wakes it does nothing else.
- `theme`: id of a theme from `GET /api/themes`. Default **`"swiss"`**, factory reset → `"swiss"`. Unknown id → `400 bad_value`.
  The speaker rebuilds its screens with the new theme at once. Stored in NVS group `display`, key `theme`.
- `night_mode`: `auto` (default: night from hour `n_from` to `n_to`, 0–23, may wrap midnight) | `on` (always) | `off`.
  Night uses the active theme's own night variant.
- `night`: legacy bool, mirrors `night_mode != "off"`. A PUT with only `night` maps `true` → `auto`, `false` → `off`;
  when both are sent, `night_mode` wins.
- `fx`: `full` (the theme's minimal effects) | `eco` (no RGB split, scanlines or tilted blocks; also switched on by
  itself on battery). The web page applies the same setting to itself (`data-fx` on `<html>`).
- `lang`: device screen language `vi` | `en`. `tz` is read-only (always `ICT-7`).

### `PUT /api/config/display`
Same shape (without `tz`), any subset, e.g. `{"theme":"zen"}`. Applied immediately. → same shape as GET.

### `GET /api/themes`
Session auth. Theme list for **Settings → Appearance**; the web builds its cards from it, so a new theme needs no web change.
```json
{"themes":[
  {"id":"swiss","name":{"vi":"Swiss","en":"Swiss"},"desc":{"vi":"Tối giản kiểu Thuỵ Sĩ, dễ đọc","en":"Minimal Swiss style, easy to read"},
   "default":true,"fx":false,"preview":"/themes/swiss.png","fonts":["archivo-vi.woff2"]},
  {"id":"brutal","name":{"vi":"Brutalism","en":"Brutalism"},"desc":{"vi":"…","en":"…"},
   "default":false,"fx":true,"preview":"/themes/brutal.png","fonts":[]}
 ],"current":"swiss"}
```
Order = display order. `fonts` = web font files in `/fonts/` used by that theme. `fx` = the `display.fx` setting
(full/saver) changes something for this theme (RGB split, scanlines, grid, HUD, tilt, segments, hard shadows); the web
UI hides that setting for themes with `fx:false`. The same data is in `web/themes.json`
(written by `tools/gen_themes.py`).

### `GET /api/theme`
**No auth**, so the login page is already themed. → `{"theme":"swiss","fonts":["archivo-vi.woff2"]}`
(`fonts` optional; without it the page loads the fonts after login).

### `GET /api/screenshot`
Session auth. The current screen as an uncompressed **BMP** (296×240, 16- or 24-bit), `Content-Type: image/bmp`,
`Cache-Control: no-store`. Optional `?tile=N` (0–4) renders that tile instead of the visible one. The Overview page
shows it, refreshing every 5 s while the tab is visible; on `404` it shows a placeholder.

## Cat (Meow Coding)

The cat tile shows the AI coding agents running on the PC (Claude Code), reported by the PC agent over `/ws/pc`
(`coding` message below). The virtual pet of 0.2.x is gone: its save `/data/cat.json` is deleted at boot.

### `GET /api/config/cat`
```json
{"name":"Mướp","fur":"tabby","clap":true,"show":true,"snd":true,
 "st":{"pc":true,"s":[{"id":"085ba2bd","ag":"claude","name":"Meow Coding cho loa","dir":"meowbox","br":"main",
   "st":"work","act":"edit","for":42,"tok":4975388,"ctx":36,"model":"Opus 5.5"}],
   "lim":{"h5":23,"h5r":1764230400,"d7":41,"d7r":1764460800}}}
```
- `fur`: `tabby` (mướp) | `orange` | `black` | `white` | `calico` (tam thể) | `gray`.
- `clap`: the cat jumps when the mics hear a clap while its tile is on screen (default `true`). Only the loudness
  is measured; nothing is recorded. Sounds the speaker plays itself are ignored.
- `show`: when a session starts waiting for the user, wake the screen and open the cat tile (default `true`).
- `snd`: a chime when a session starts waiting, a meow (not in night mode) when a session finishes (default `true`).
- `st` is read-only: `pc` = agent connected; `s` = the sessions, most urgent first (at most 4), empty when the agent
  is gone or sent nothing for 75 s. Per session: `st` = `wait` (a permission prompt or a question) | `work` | `err` |
  `done` | `idle`, `for` = seconds in that state, `act` = the kind of tool call: `read` | `image` | `edit` |
  `write` | `bash` | `search` | `web` | `agent` | `plan` | `ask` | `skill` | `compact` | `tool` (anything else), `""`
  while thinking. The speaker and the web page word it ("Đang đọc file"); no file names or commands leave the PC. `tok` = tokens processed (input + output + cache),
  `ctx` = context window used in % (absent until known), `model` = `Opus 5.5`... `lim` (absent for API-key use or
  before Claude Code's status line has run): the Claude plan's usage limits in %, `h5` = 5-hour window, `d7` = weekly,
  `h5r` / `d7r` = when they reset (epoch seconds). The tile shows `5h 23%`.

### `PUT /api/config/cat`
`{"name":"Mun","fur":"black","clap":false,"show":true,"snd":false}` (`name` ≤ 16 bytes) → same shape as GET.

## Notifications

### `GET /api/config/notify`
```json
{"token":"q7Lw2xK9pR4tY8vZ","dur":10,"vol":70,"quiet_low":true}
```
- `token`: 16 chars `[A-Za-z0-9]`, generated at first boot.
- `dur`: default overlay seconds. `vol`: sound volume 0–100 (radio is ducked while it plays).
- `quiet_low`: `low` priority makes no sound during night hours.

### `PUT /api/config/notify`
`{"dur":10,"vol":70,"quiet_low":true}`, or `{"regen":true}` to create a new token
(the old one stops working at once). → same shape as GET.

### `POST /api/notify`
```
Authorization: Bearer q7Lw2xK9pR4tY8vZ
{"title":"Build xong","text":"esp32-playground OK","sound":"chime","priority":"normal","duration":10}
```
- `text` required (≤ 200 bytes), `title` optional (≤ 48 bytes).
- `sound`: `chime` | `alert` | `none` (default `chime`). `priority`: `low` | `normal` | `high` (default `normal`).
  `high` turns the screen on and sounds even at night. `duration`: seconds (default `dur`, 1–300).
- → `{"ok":true,"id":17}`. Queue holds 10; when full → `429 queue_full`.

### `GET /api/notify?text=...&token=...`
Short form for scripts/phones. Optional `title`, `sound`, `priority`, `duration` query params, URL-encoded.
→ same as POST.

### `POST /api/notify/audio`
Body = raw WAV or MP3 file (≤ 1 MB), `Content-Type: audio/wav` or `audio/mpeg`, Bearer token. Optional
`?title=&text=` to also show an overlay. → `{"ok":true,"id":18}`; too big → `413 too_large`. WAV must be 16-bit PCM
at 8–96 kHz; other WAVs play nothing.

### `GET /api/notify/history`
Last 20, newest first (RAM only):
```json
{"items":[{"id":17,"ts":1763791100,"title":"Build xong","text":"esp32-playground OK","sound":"chime","priority":"normal","src":"api"}]}
```
`src`: `api` | `pc` | `audio`.

## PC agent

### `GET /api/config/pc`
```json
{"host":"192.168.1.10","port":8765,"auto":true,
 "st":{"on":true,"name":"DESKTOP-MEO","ip":"192.168.1.10","ver":"0.2.0","proto":1,"proto_need":1,"seen":1}}
```
- `host`/`port`: the agent's HTTP relay used for YouTube stations (`http://host:port/yt/stream?url=...`).
- `auto`: take the relay address from the connected agent's `hello` instead of `host`.
- `st` is read-only: `on` = agent connected to `/ws/pc`, `seen` = seconds since last message, `name`/`ver`/`proto`
  from the agent's `hello` (`proto` -1 = no agent since boot, 0 = agent before 0.2.0), `proto_need` = protocol this
  firmware speaks: an agent with a lower `proto` should be updated.

### `PUT /api/config/pc`
`{"host":"192.168.1.10","port":8765,"auto":false}` → same shape as GET.

### `POST /api/pc/relay_test`
Token or web session. Body `{}`. The speaker itself calls `GET http://<relay>/yt/ping` (3 s timeout): the only way to
know YouTube will play, since a PC firewall blocks speaker → PC, not PC → speaker.
→ `{"ok":true,"relay":"192.168.1.10:8765","ms":12}` or `{"ok":false,"relay":"…","err":"timeout"}`
(`err`: `no_relay`, `timeout`, `unreachable`, `http_<code>`).

### `GET /api/ping`
**No auth.** → `{"name":"MeowBox-1A2B","host":"meowbox-1a2b","ver":"0.2.0","proto":1,"proto_min":0,"mac":"…"}`.
Lets the agent check that an IP is a MeowBox, and which one. `mac` is for a DHCP reservation on the router.

### `GET /api/debug`
Session auth. Memory and per-task numbers, read by `firmware/tools/memwatch.py`:
```json
{"up_ms":198000,"int":{"free":47303,"min":7796,"big":32768,"tot":330091},"dma":{...},"psram":{...},
 "rt_total":198000000,"tasks":[{"name":"taskLVGL","prio":4,"core":1,"stack_free":2300,"stack_ext":false,"rt":559293}]}
```
`min` is the lowest free since boot, `big` the largest free block. `stack_free` is the task's lowest free stack in
bytes, `stack_ext` true when that stack is in PSRAM. `rt` is the raw run-time counter: CPU % = Δrt / Δrt_total
between two calls (one core = 100 %). Not in `mock_server.py`.

### `GET /api/log`
Session auth. Why the speaker last started, and its error/warning log lines (System page, "Error log"):
```json
{"boot":7,"reason":"task_wdt","up_s":95,
 "prev":{"up_s":18234,"int_free":41210,"int_min":39480},
 "prev_log":["W (18201345) player: underrun 1, prebuffer now 4 s","E (18233977) task_wdt: ..."],
 "log":["W (912) lcd_panel.nv3023: ..."],
 "boots":[{"n":7,"reason":"task_wdt","up_s":0,"int_min":0},{"n":6,"reason":"sw","up_s":18234,"int_min":39480}]}
```
- `reason`: `power_on` | `sw` (restart, update) | `panic` | `task_wdt` | `int_wdt` | `wdt` | `brownout` | `usb` (reset by
  the USB serial port, e.g. flashing) | `ext` | `deepsleep` | `unknown`.
- `prev_log` / `prev`: every `E`/`W` log line of the previous run (the newest ~2 KB) and its last uptime / internal RAM
  snapshot (taken every 2 s). Kept in RTC memory, so they survive a restart, crash or watchdog reset but not a power
  off: then `prev` is `null` and `prev_log` empty. A UI task that gets no CPU for 10 s logs
  `E diag: UI task got no CPU for N s (screen frozen)`.
- `log`: the same for the current run. `boots`: the last 10 starts, newest first, stored in `/data/boots.json`; `up_s` /
  `int_min` of an entry are filled in at the next start (0 for the current one).

### `/ws/pc` protocol (agent ↔ speaker)
- Agent → speaker first message: `{"t":"hello","name":"DESKTOP-MEO","ver":"0.2.7","proto":2,"token":"<notify token>",
  "relay":"http://ip:8765"}`, optional `"take":true`. Then `stats` / `media` every second, `notify`, `coding`.
  Protocol 2 (0.2.7): the hello must carry the notify token, else `{"t":"auth"}` and close; any other first message
  closes the connection. `relay` is used only if its IP is the agent's own address, and only while that agent stays
  connected. A WebSocket upgrade with an `Origin` header (a web page) is refused.
- `coding` (Meow Coding, agent 0.2.4+): `{"t":"coding","s":[{"id":"085ba2bd","ag":"claude","name":"…","dir":"meowbox",
  "br":"main","st":"work","act":"edit","for":42,"tok":4975388,"ctx":36,"model":"Opus 5.5"}]}`, sent
  when the list changes (at most once a second) and every 30 s. Fields as in `GET /api/config/cat`; `ctx` is left out
  until known; `lim` as in `GET /api/config/cat`, sent once Claude Code's status line has reported it. Firmware before
  0.2.4 ignores it. The agent learns the sessions from Claude Code's hooks
  (background `curl` to `http://127.0.0.1:8767/hook` with a per-install key header, installed by `meowbox coding install` or the tray menu) and reads each
  session's transcript for tokens, context and title. The plan's usage limits and the exact context use come from
  Claude Code's status line (`curl ... http://127.0.0.1:8767/status`, also installed when no status line is set).
- Speaker → agent: `media_cmd`; `{"t":"auth"}` then close (missing or wrong token); `{"t":"busy","pc":"OTHER-PC"}` then close (one PC at a time: another PC is connected,
  or this one was taken over; a hello with `take:true` takes over, the same PC name reconnecting is let in);
  `{"t":"proto","need":N,"have":M}` then close when the agent's `proto` is below the firmware's minimum.

### Discovery
- mDNS: host `meowbox-xxxx.local`, service `_meowbox._tcp` with instance = speaker name and TXT `ver`, `proto`.
- UDP: datagram `MEOWBOX?` to port 8766 (broadcast) → unicast reply
  `{"name":"MeowBox-1A2B","ip":"192.168.1.42","ver":"0.2.0","proto":1}` (home Wi-Fi only, ≤ 5 replies/s).

## System

### `POST /api/ota`
Body = raw firmware `.bin` (`Content-Type: application/octet-stream`, `Content-Length` required, max
5 505 024 bytes = size of `ota_1`). The firmware streams it into the inactive OTA slot (`esp_ota_write`), checks
the image, sets it as boot partition, replies, then reboots after ~1 s. The new image must call
`esp_ota_mark_app_valid_cancel_rollback()` after a healthy start, otherwise the bootloader rolls back.
→ `{"ok":true}`. Errors: `400 bad_image` (wrong magic `0xE9`/validation failed), `413 too_large`.

### Update (GitHub Releases)
The speaker reads `manifest.json` of the latest release (`CONFIG_MEOWBOX_UPDATE_MANIFEST_URL`, default
`https://github.com/phuc4real/meowbox-esp32/releases/latest/download/manifest.json`, written by `tools/release.py`):

```json
{"ver":"0.2.1","proto":1,"date":"2026-12-01","notes":{"vi":["…"],"en":["…"]},
 "app":{"file":"meowbox-0.2.1.bin","url":"https://github.com/…/releases/download/v0.2.1/meowbox-0.2.1.bin",
        "size":3155424,"sha256":"…64 hex…"},
 "min_ver":"0.1.0","page":"https://github.com/…/releases/tag/v0.2.1","commit":"3ac11f9"}
```

By default it only checks when asked (`POST /api/update/check`). `PUT /api/config/update {"auto":true}` adds a check
2 min after Wi-Fi comes up and then every 24 h. Versions compare as numbers (`0.10.0` > `0.9.0`).

`GET /api/update` →
`{"cur":"0.2.0","state":"idle","pct":0,"err":"","auto":false,"checked":1764460800,"latest":"0.2.1","new":"0.2.1",
"date":"2026-12-01","size":3155424,"proto":1,"usb_only":false,"notes":{"vi":[…],"en":[…]},"page":"…",
"last":{"ver":"0.2.1","err":""}}`
- `state`: `idle` | `check` | `download` | `verify` | `reboot` | `error` (`err` says why: `offline`,
  `no_release` (GitHub answered 404: nothing published yet), `manifest_unreachable`, `bad_manifest`, `download`, `bad_hash`, `bad_image`, `no_mem`). `pct` while downloading.
- `new`, `date`, `size`, `proto`, `usb_only`, `notes` only when the latest release is newer than `cur`. `usb_only`:
  `cur` is older than the manifest's `min_ver`, so installing over the air is refused.
- `last`: outcome of the install started before this boot: `err` `""` (now running `ver`) or `rollback` (the new image
  did not start properly and the bootloader went back).
- `GET /api/status` gains `"upd":"0.2.1"` while a newer release is known.

`POST /api/update/check` body `{}` → same as `GET /api/update` with `state` `check`; poll `GET` until it leaves
`check`. `409 offline` without Wi-Fi, `409 busy` while installing.

`POST /api/update` body `{"ver":"0.2.1"}` → starts installing, same body as `GET` with `state` `download`. Errors
(`409`): `stale` (`ver` is not the newer release from the last check), `usb_only`, `low_battery` (under 30% and not
charging), `busy`. The speaker stops playback, keeps Wi-Fi out of power save, downloads into the free OTA slot, checks
size and SHA-256 of what was written against the manifest, sets the boot slot and restarts (`state` `reboot`).
Any failure before that leaves the running version untouched.

### `POST /api/reboot`
Body `{}` → `{"ok":true}`, reboots after ~1 s.

### `POST /api/factory_reset`
Body `{"confirm":true,"scope":"all"}` → `{"ok":true}`, then the speaker reboots. Without `confirm:true`, or with
another `scope` → `400 bad_value`.
- `scope` `"all"` (default, **Factory reset** on the web page): formats `/data` (Wi-Fi list, stations, alarms, cat
  settings, battery log, password, token, every setting) and drops the networks the vendor firmware left in NVS. The speaker
  comes back in setup mode (SoftAP portal), login `meowbox` / `m3owb0x2026`.
- `scope` `"data"` (**Clear data**): at the next boot deletes everything in `/data` except the configuration
  (`cfg/`, `auth.json`, `wifi.json`): battery log and sessions, update outcome. The
  notification history is in RAM and goes with the reboot. Settings, Wi-Fi, stations, alarms, password and token stay.

## Battery

### `GET /api/battery` (session)
```json
{"pct":82,"raw":2330,"mv":4020,"chg":false,"rate":12.0,"eta":310,
 "cur":{"open":true,"start":1763791200,"min":80,"from":100},
 "sessions":[{"start":1763700000,"min":412,"from":100,"to":6,"mv_from":4180,"mv_to":3400,
              "bri":62,"play_min":180,"end":"empty","full_h":7.3}],
 "pts":[[1763791200,100.0,4180],[1763791260,99.8,4176]]}
```
- `pct` smoothed 0–100, `mv` calibrated battery voltage (assumes a 1:2 divider), `rate` discharge %/h over the last
  60 min, `eta` estimated minutes left (`-1` unknown or charging).
- `cur`: the running battery session (since unplugging). `sessions`: last 10 finished sessions, newest first;
  `end` = `plugged` | `empty` | `off`; `full_h` = projected 100→0 % runtime (only when ≥ 5 % was used).
- `pts`: up to 240 samples `[unix, pct, mv]` of the current (or last) session for a chart.

### `GET /api/battery/log.csv` (session)
Raw per-minute log while on battery: `ts,raw,mv,pct,brightness,volume,radio`.
